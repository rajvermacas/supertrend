# Backtesting Engine Design

This document outlines the design and rules for the backtesting engine that will be used to simulate our Supertrend trading strategy.

## 1. Trade Execution Logic

The engine will simulate trades based on the signals generated by the strategy.

- **System Type**: We will use a **"stop-and-reverse"** system. This means the strategy is always in the market, either in a long or a short position.
- **Execution Assumption**: Trades will be simulated as executing at the **closing price** of the hourly candle that generates the signal.
- **Trade Flow**:
    - On a **Buy Signal**: Any open short position is closed, and a new long position is opened.
    - On a **Sell Signal**: Any open long position is closed, and a new short position is opened.

## 2. Key Performance Metrics

To evaluate the strategy's performance, the engine will calculate several key metrics.

- **Win Rate (Primary Metric)**: The percentage of trades that result in a profit. This is our main target for optimization.
  - `Formula: (Number of Winning Trades / Total Number of Trades) * 100`
- **Total Profit/Loss (P/L)**: The net cumulative profit or loss over the entire backtesting period.
- **Maximum Drawdown**: The largest peak-to-trough decline in portfolio value, expressed as a percentage. This is a critical measure of risk.
- **Total Number of Trades**: The total count of trades executed during the backtest period.

## 3. Backtesting Process

The core of the engine will be a loop that iterates through the historical hourly data, candle by candle. It will:
1.  Calculate the indicator values for the current candle.
2.  Check for new buy/sell signals based on the strategy logic.
3.  Execute trades and update the portfolio's state (position, equity).
4.  Log each trade for final performance analysis.
